# 唤醒词「Hey Jarvis」制作 / 自训教程

> 适配：`jarvis_console` 融合版 JARVIS v1 · `sherpa-onnx==1.12.40` KWS（关键词 spotting）  
> 目标：让离线唤醒 "Hey Jarvis" 真正跑通，并给出误唤醒/唤醒率调参方法。

---

## 0. 一句话结论

`sherpa-onnx` 的 KWS **不一定要从零训练**：用官方预训练 KWS 模型 + 一个 `keywords.txt` 就能跑「Hey Jarvis」。  
只有当所选模型的词表（`tokens.txt`）覆盖不到 "JARVIS" 的分词时，才需要走**自训**（路线 B）。

---

## 1. 先对齐代码：`wake.py` 到底怎么加载

`jarvis_console/speech/wake.py` 的行为 ：

| 项     | 约定                                                                                                |
| ----- | ------------------------------------------------------------------------------------------------- |
| 模型目录  | `jarvis_console/models/wakeword/`（`paths.WAKE_MODEL`）                                             |
| 必需文件  | `encoder.onnx`、`decoder.onnx`、`joiner.onnx`、`tokens.txt`（官方包是长命名，脚本/首启向导会自动归一化，见 2.2）                                          |
| 构造方式  | `sherpa_onnx.KeywordSpotter(tokens=..., encoder=..., decoder=..., joiner=..., keywords_file=...)` |
| 关键词文件 | `keywords.txt` **必需**；目录里没有、或内容不含当前唤醒词时，程序自动切成 **官方风格 token 序列** 并生成（官方示例词会备份为 `keywords.official.txt`）                       |
| 阈值    | `keywords_threshold=0.25`（与 sherpa 官方一致，**0.35 会漏检**）、`num_trailing_blanks=4`、`keywords_score=1.0`          |
| 中文路径  | 已用 `load_model_safely`：chdir 到模型目录 → 只传纯文件名 → finally 恢复，规避 exit 127                              |

> ⚠️ 历史坑：`sherpa-onnx 1.12.40` **没有** `KeywordSpotterConfig` 类，必须直接传参构造。本仓库已修正。

### 1.1 四个实测铁律（2026-10-30 用官方模型 + 官方测试音频逐条验证）

| # | 铁律 | 违反的后果 |
|---|---|---|
| 1 | `keywords.txt` **只写 token 序列，不加 `@显示文本`** | 报 `Cannot find ID for token Jarvis`，进程 **exit 127**（`@` 是 Porcupine 语法，sherpa 不认） |
| 2 | 按词切分，**每个词的首 token 带词界标记 `▁`**（`LIGHT UP` → `▁ L IGHT ▁UP`） | 少了词首 `▁`（如 `L IGHT ▁UP`）**检不出关键词**——声学模型按词界 token 输出音频，对不上 |
| 3 | **必须分块喂音频**（约 0.1s/块；`audio_service` 天然如此） | 整段一次性 `accept_waveform` 不触发命中 |
| 4 | `keywords_threshold` 用 **0.25** 而非 0.35 | 0.35 下官方测试音频全部漏检 |

另两个易错点：`get_result()` 返回的是**字符串**（命中即关键词文本，未命中 `''`），不是带 `.keyword` 属性的对象；`keywords.txt` 里任何**不存在的 token** 都会让加载直接 abort（exit 127），写入前必须校验。

> 以上全部内建在 `speech/kws_tokens.py`（分词 + 校验）、`speech/wake.py`（阈值 / 结果解析 / 分块解码）与一键脚本里，**无需手动处理**；理解它们有助于排错。

## 1.5 一键脚本（最省事，先跑这个）

把「下载 → 解压 → 生成 keywords.txt → 加载自测」四步压成一条命令：

```bat
REM 一键（双击也行）：tools\setup_wakeword.bat
.venv\Scripts\python.exe tools\kws_setup.py
```

脚本会依次做：

1. 检查 `jarvis_console\models\wakeword\` 是否已就绪（4 个模型文件 + `keywords.txt`）；
2. 缺失则下载官方预训练英文 KWS 模型（gigaspeech 3.3M-2024-01-01，约 17.6MB；主源失效自动回退 wenetspeech / zh-en 两个备选源；复用 `download_models.py` 的断点续传 + sha256 校验）；
3. 自动把官方长命名 onnx 归一成 `encoder/decoder/joiner.onnx`（优先 int8），再用 `tokens.txt` 按**官方风格**（按词切分、词首带 `▁`）切出 "Hey Jarvis" 并写出 `keywords.txt`；官方包自带的示例 keywords.txt 会被备份为 `keywords.official.txt`；
4. 用与线上**完全相同**的加载路径（`speech/wake.py` 的 `WakeEngine`）真实加载一次，确认模型可用。

常用变体：

```bat
REM 国内网络走 GitHub 加速镜像
.venv\Scripts\python.exe tools\kws_setup.py --mirror

REM 完全离线：本地压缩包安装
.venv\Scripts\python.exe tools\kws_setup.py --archive D:\kws.tar.bz2

REM 用现成 16k 单声道 wav 验证唤醒命中
.venv\Scripts\python.exe tools\kws_setup.py --test-wav D:\hey_jarvis.wav

REM 录 6 秒麦克风，说「Hey Jarvis」验证命中
.venv\Scripts\python.exe tools\kws_setup.py --record 6

REM 强制重下 + 换唤醒词
.venv\Scripts\python.exe tools\kws_setup.py --force --keyword "Hey Jarvis"
```

| 参数                          | 作用                           |
| --------------------------- | ---------------------------- |
| `--mirror`                  | 走 GitHub 加速镜像（镜像可用性会变，失败就去掉） |
| `--archive <包>`             | 本地压缩包，完全离线                   |
| `--sha256 <值>`              | 提供则严格校验下载完整性                 |
| `--force`                   | 忽略已有文件，重新下载/解压/生成            |
| `--skip-download`           | 只做检查/分词/自测，不下载               |
| `--test-wav` / `--record N` | 音频命中自测（录音需 `sounddevice`）    |

退出码：`0` = 模型就绪；`1` = 硬失败（下载/解压/分词失败或加载不通过）。  
脚本只做「配置 + 自测」，不启动主程序；跑完后按第 6 节清单启动总控台即可。

> 下面第 2 节起是同一件事的**手工版**（理解原理 / 排错 / 自训时看），一键脚本失败时按它逐段排查。

## 2. 路线 A：预训练模型 + 自定义关键词（推荐，最快）

### 2.1 下载预训练 KWS 模型

英文场景推荐（词表覆盖常见英文词）。以下 URL 均来自官方 `kws-models` release，并**实测可下载**（2026-10-30）：

| 模型 | 体积 | 适用 |
|---|---|---|
| `sherpa-onnx-kws-zipformer-gigaspeech-3.3M-2024-01-01.tar.bz2` | ~17 MB | 英文唤醒词（**推荐**，"Hey Jarvis"） |
| `sherpa-onnx-kws-zipformer-wenetspeech-3.3M-2024-01-01.tar.bz2` | ~33 MB | 中文向备选（英文词覆盖较弱） |
| `sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20.tar.bz2` | ~33 MB | 中英混合新版（中文口音英语识别更好） |

官方 Release（`kws-models` tag）：

```text
https://github.com/k2-fsa/sherpa-onnx/releases/download/kws-models/sherpa-onnx-kws-zipformer-gigaspeech-3.3M-2024-01-01.tar.bz2
```

> 国内加速：URL 前加 `https://ghproxy.net/`（`tools\kws_setup.py --mirror` 默认用的就是它）。
> 也可以直接跑 1.5 节的一键脚本，它会按上表顺序自动尝试，主源失效自动换下一个。
> ⚠️ 网上流传的 `gigaspeech-3.4M-2023-12-09` 这个文件名在官方 release 里**不存在**（会 404），别用。

### 2.2 放到模型目录

⚠️ 官方包的 onnx **不是** `encoder.onnx` 这个名字，而是
`encoder-epoch-12-avg-2-chunk-16-left-64.int8.onnx` 这类长命名（还有 fp32 非 int8 版本）。
`wake.py` 按短名加载，所以要**改名**（优先 int8）：

```bat
REM 一键脚本/首启向导会自动做这件事；手动改名的等价写法：
cd jarvis_console\models\wakeword
ren "encoder-epoch-12-avg-2-chunk-16-left-64.int8.onnx" encoder.onnx
ren "decoder-epoch-12-avg-2-chunk-16-left-64.int8.onnx" decoder.onnx
ren "joiner-epoch-12-avg-2-chunk-16-left-64.int8.onnx" joiner.onnx
```

最终目录应有 **4 个短名文件**：

```text
encoder.onnx
decoder.onnx
joiner.onnx
tokens.txt
```

### 2.3 生成 `keywords.txt`

**方式 A（自动）**：直接启动 `jarvis_console`，首次进入语音链路时 `wake.py` 会自动生成 `keywords.txt`（日志会打印「已生成唤醒词 keywords.txt：…」）。**最省事的是 1.5 节的一键脚本**（`tools\kws_setup.py`），它连模型下载一起包办了。

**方式 B（手动/预览分词）**：用仓库自带小工具：

```bat
.venv\Scripts\python.exe tools\kws_make_keywords.py ^
    --model-dir jarvis_console\models\wakeword ^
    --keyword "Hey Jarvis"
```

它会把 "Hey Jarvis" 按 `tokens.txt` 的词表切成 token，并写入 `keywords.txt`；加 `--dry-run` 只打印不写。

**手写格式**（每行一条；**纯 token 序列，不加 `@显示文本`**；按词切分、词首带 `▁`）：

```text
▁HE Y ▁JA R VI S
```

> 左边每个 token 必须是 `tokens.txt` 里真实存在的——**一个不存在的 token 就会让加载直接 exit 127**。
> 词首必须带 `▁`（词界标记），否则检不出关键词（见 1.1 铁律 2）。
> 用 `--dry-run` 或看生成的 `keywords.txt` 确认。

### 2.4 自测（不启动主程序）

准备一段你自己说 "Hey Jarvis" 的 **16k 单声道 wav**，用下面脚本验证：

```python
import wave
import numpy as np
import sherpa_onnx

model_dir = r"jarvis_console\models\wakeword"
spotter = sherpa_onnx.KeywordSpotter(
    tokens=f"{model_dir}\\tokens.txt",
    encoder=f"{model_dir}\\encoder.onnx",
    decoder=f"{model_dir}\\decoder.onnx",
    joiner=f"{model_dir}\\joiner.onnx",
    keywords_file=f"{model_dir}\\keywords.txt",
    num_threads=1, sample_rate=16000, feature_dim=80,
    keywords_score=1.0, keywords_threshold=0.25, num_trailing_blanks=4,
    provider="cpu",
)
stream = spotter.create_stream()
with wave.open(r"your_hey_jarvis.wav", "rb") as w:
    assert w.getframerate() == 16000 and w.getnchannels() == 1, "需 16k 单声道 wav"
    pcm = np.frombuffer(w.readframes(w.getnframes()), dtype=np.int16).astype(np.float32) / 32768.0

# 必须分块喂（约 0.1s/块）；get_result() 返回字符串，命中即关键词文本
for start in range(0, len(pcm), 1600):
    stream.accept_waveform(16000, pcm[start:start + 1600])
    while spotter.is_ready(stream):
        spotter.decode_stream(stream)
    result = spotter.get_result(stream)
    if result:  # 非空字符串即命中
        print("HIT:", result)
        spotter.reset_stream(stream)
```

命中会打印关键词；不命中就换个模型或走路线 B。

### 2.5 路线 A 的局限

若 `wake.py` 报 **「无法用 tokens.txt 的词汇切分唤醒词」**，说明该模型词表覆盖不到 "JARVIS"（例如纯中文词表）。此时：

- 换词表更全的英文 KWS 模型；或
- 手写一个只含可用 token 的 `keywords.txt`；或
- 走路线 B 自训。

## 3. 路线 B：自训专属「Hey Jarvis」KWS（词表/效果不满足时）

### 3.1 环境

- Linux + NVIDIA GPU（推荐；CPU 也能训但慢），Python 3.10，PyTorch，`k2` / `icefall`。
- Windows 也能跑，但建议 WSL2 或云 GPU。

### 3.2 数据

- **正样本**：2000–5000 条，不同人、不同距离/噪声/语速说 "Hey Jarvis"，16k 单声道 wav。
- **负样本 / 背景**：公开噪声集 + 其它语音（用于压低误唤醒）。
- 每条 wav 配 `text`（`HEY JARVIS`）与 `keywords` 标注。

### 3.3 训练（基于 icefall KWS recipe，finetune 预训练模型最省数据）

```bash
git clone https://github.com/k2-fsa/icefall
cd icefall/egs/gigaspeech/KWS
# 1) 按该目录 README 准备 wav.scp / text / keywords 清单
bash prepare.sh
# 2) 用预训练 KWS checkpoint 做 finetune（少量数据也能收敛）
bash train.sh
```

> 具体超参与目录结构以 icefall 官方 `egs/gigaspeech/KWS` recipe 为准；上面的命令是流程骨架。

### 3.4 导出 ONNX

```bash
python3 export-onnx.py --epoch <N> --avg <K>
```

导出得到 `encoder.onnx`、`decoder.onnx`、`joiner.onnx`、`tokens.txt`（与 sherpa-onnx 命名一致）。

### 3.5 接入本仓库

把导出文件拷到 `jarvis_console\models\wakeword\`，再按 2.3 生成 `keywords.txt` 即可。

## 5. 调参与误唤醒控制

| 参数                    | 位置                | 作用             | 建议               |
| --------------------- | ----------------- | -------------- | ---------------- |
| `keywords_threshold`  | `wake.py` 构造处（默认 0.25） | 越高越难触发、误唤醒越少 | 0.15–0.5：漏唤醒调低、误唤醒多调高 |
| `keywords_score`      | `wake.py` 构造处     | 关键词加分权重，越高越敏感  | 1.0 起，唤醒难就略升     |
| `num_trailing_blanks` | `wake.py` 构造处     | 尾部静音帧，防一句话反复触发 | 2–6              |
| 多关键词                  | `keywords.txt` 多行 | 支持多个唤醒词        | 每行一条             |

## 7. 常见问题（FAQ）

**Q1：报 `module 'sherpa_onnx' has no attribute 'KeywordSpotterConfig'`？**  
A：`1.12.40` 没有该配置类，必须用 `KeywordSpotter(tokens=..., encoder=..., ...)` 直接构造。本仓库已修正。

**Q1b：报 `Cannot find ID for token Jarvis` 然后进程退出（exit 127）？**
A：`keywords.txt` 里写了 `tokens.txt` 中不存在的 token——最常见原因是加了 `@显示文本` 后缀（sherpa 不支持，`@Hey Jarvis` 里的 "Jarvis" 会被当 token 查表）。改成纯 token 序列即可；本仓库的 `kws_tokens.py` 会在写入前校验，挡掉这类崩溃。

**Q2：报「无法用 tokens.txt 的词汇切分唤醒词」？**  
A：模型词表不含 "JARVIS" 的分词。换模型 / 手写 `keywords.txt` / 走路线 B。

**Q3：中文路径下加载模型 exit 127？**  
A：必须 chdir 到模型目录再传纯文件名。本仓库已用 `load_model_safely` 处理；自己写脚本也要照做。

**Q4：误唤醒太多？**  
A：提高 `keywords_threshold`、加长唤醒词、补充负样本/背景噪声；也可换更大的 KWS 模型。

**Q5：唤醒不了？**  
A：确认 wav 是 16k 单声道、麦克风有输入、`keywords.txt` 的 token 与 `tokens.txt` 一致；降低 `keywords_threshold` 试。
