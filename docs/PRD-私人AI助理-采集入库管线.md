## 1. 目标与范围

### 1.1 阶段一（本期交付）
- **IN（采集）**：定时自动从 小红书 / 抖音视频 / 关注网页 抓取内容。
- **PROCESS（整理）**：去重、清洗、结构化、摘要（本地优先，摘要环节允许走 DeepSeek）。
- **OUT（入库）**：写入本地个人知识库（向量检索 + 原文落盘）。
- **检索**：支持语义检索，供后续阶段（对话/简报）调用。

### 1.2 明确不在本期范围（避免范围蔓延）
- 语音唤醒 / 语音布置任务 / 隔空操控电脑（属另一既有并行线，见 §6 备注）。
- 微信相关抓取（已知微信 4.x 自绘后 UIAutomation 失效，本期不碰）。
- 跨设备同步、手机端、公网暴露。
- 知识库的对外分享/发布。

### 1.3 成功标准（可验收）
1. 调度器能按设定周期**自动唤起**采集（无需人工点按）。
2. 三类来源**至少各跑通一条**端到端采集链路（能从源到库）。
3. 入库内容可被**语义检索**命中，且保留原文可回溯。
4. 全程**本地模型优先**，仅"摘要质量敏感"环节允许调用 DeepSeek，且 API Key 不落库明文。

## 2. 架构总览：Aivy OS 能力 → 自研模块映射（借鉴而非照搬）

> 以下模块均运行在本机（Win11），硬件已确认足够。子智能体/自唤醒/任务看板是**软件层机制，不额外吃显存**，主要资源消耗在模型推理本身——16GB 显存已满足。

| Aivy OS 机制 | 我们的自研对应 | 实现要点 |
|---|---|---|
| 子智能体后台并行 | **采集 Worker 池**（asyncio 并发） | 小红书 / 抖音 / 网页 三个采集器并发，互不阻塞 |
| 自唤醒 / 定时 | **调度器**（APScheduler 或 Windows 任务计划） | 按 cron 自己醒来跑采集 |
| Mission 长任务 / 任务看板 | **任务状态库**（SQLite + 看板页） | 跨天续跑、失败重试、进度可见 |
| Wiki 知识库 + 向量检索 | **本地向量库 + 原文库** | Chroma/Qdrant + Markdown/Parquet 原文 + 嵌入模型 |
| 浏览器自动化 | **Playwright** | 对付小红书/抖音/JS 动态网页，需注入登录态 cookie |
| 多模态视觉解析 | **视频转文本管线** | 抖音：音频 ASR（本地 whisper）+ 关键帧 OCR/多模态 → 文本入库 |
| 模型服务（模型无关） | **Ollama + DeepSeek 双引擎路由** | 本地 qwen3-14b 做整理/嵌入兜底；DeepSeek 做高质量摘要 |

| 层 | 选型（候选/推荐） | 说明 |
|---|---|---|
| 运行时 | Python 3.12（本机已装 3.12.10） | 沙箱踩坑：pip 需 `--timeout 15 --no-cache-dir`；GitHub Releases 下不动，走镜像 |
| 调度 | APScheduler（内嵌）或 Windows 任务计划程序 | 自唤醒的承载 |

| 嵌入模型 | Ollama 嵌入模型（如 `nomic-embed-text` / `bge-m3`） | 本地生成向量，不依赖云端 |
| 本地推理 | Ollama `qwen3-14b` Q4 | 整理/抽取/兜底摘要 |
| 云端摘要 | DeepSeek API（模型字段 `deepseek-flash`） | 高质量中文摘要，仅摘要环节用；OpenAI 兼容，base_url `https://api.deepseek.com` |
| 原文存储 | Markdown / Parquet + SQLite 元数据 | 可回溯、可迁移 |

| 看板 | 轻量 Web（FastAPI + 极简前端）或 CLI 状态页 | 取决于用户要"看得见"还是"够用就行" |
| 视频处理 | `whisper`（本地 ASR）+ OpenCV（关键帧）+ 可选多模态 | 抖音视频转文本 |

> ⚠️ 待查证项：DeepSeek 当前定价/额度、具体嵌入模型选型、看板是否需要 GUI。这些在 PRD 拍板后实现前再核。

## 4. 模块划分与数据流

```
[调度器 自唤醒]
      │  cron 触发
      ▼
[采集层]  小红书 Worker ┐
          抖音 Worker   ├─(并发, asyncio)─► [解析/清洗层]
          网页 Worker   ┘                     │ 去重、正文提取、OCR/ASR
      │                                      ▼
      │                              [整理/摘要层]
      │                               本地 qwen3-14b 抽取结构化
      │                               敏感质量环节 → DeepSeek 摘要
      │                                      │
      │                                      ▼
      └──────[任务状态库 SQLite]◄────[入库层]
                                      │ 原文落盘 + 嵌入向量
                                      ▼
                              [知识库] Chroma(向量) + 原文(MD/Parquet)
                                      │
                                      ▼
                              [检索接口] 语义检索（供后续对话/简报调用）
```

- **采集层**：每源一个 Worker，登录态 cookie 本地加密存储，遵守速率限制。
- **解析层**：网页用 `trafilatura`/`readability` 抽正文；小红书/抖音用 Playwright 渲染后抽；抖音额外走 ASR+关键帧。
- **整理层**：本地模型做字段抽取/结构化；仅"摘要"可路由 DeepSeek。
- **入库层**：写入原文 + 生成嵌入 + 更新任务状态。
- **看板**：读 SQLite 渲染进度/失败。

## 5. 各采集器可行性与合规风险（必须正视）

| 来源 | 技术可行性 | 合规/平台风险 | 本期策略 |
|---|---|---|---|
| **关注网页** | 高（RSS / 直抓 / 搜索） | 低（遵守 robots、限频） | 最先做，作为打通管线的基础 |

> 事实声明：上述"可行性/风险"是基于公开认知的**评估**，非已实测结论。真正强度需在 M2–M4 各采集器实现时实测，并按平台条款与"个人非商用、限频、不转售"原则收敛。

- **峰谷定价**（2026-08-17 起生效）：高峰时段为北京时间 **9:00–12:00、14:00–18:00**，其余为空闲时段，空闲价为高峰一半。

  - 输入（缓存命中）：空闲 **$0.006** / 高峰 **$0.044**
